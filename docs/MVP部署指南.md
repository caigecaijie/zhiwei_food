# 智味菜谱 MVP 部署指南

本文档指引如何在微信开发者工具中部署并跑通 MVP 第一阶段（菜谱管理、购物车下单、邀请下单/饭局点菜、按食材配菜）。

## 一、前置条件

- 微信开发者工具（最新稳定版），已导入本项目，AppID 填入你自己的小程序 AppID
- 已注册微信小程序账号，并具备云开发权限

## 二、开通云开发环境

1. 在开发者工具顶部点击 **「云开发」**，按提示开通（选择按量付费免费额度即可）。
2. 记下环境 ID（形如 `cloud1-xxxx`）。
3. 打开 `miniprogram/app.ts`，在 `wx.cloud.init` 中显式指定环境：

```ts
wx.cloud.init({
  env: '你的环境ID',
  traceUser: true,
})
```

> 未指定 env 时使用默认环境，单环境也可直接运行；多环境必须指定。

## 三、部署云函数（共 5 个）

云函数位于 `cloudfunctions/` 目录：

| 云函数 | 作用 |
| --- | --- |
| `initDatabase` | 初始化数据库集合 |
| `userManage` | 登录 / 资料管理 / 新用户默认分类 |
| `recipeCRUD` | 菜谱与分类增删改查 |
| `orderManage` | 购物车 / 订单 / 饭局 |
| `matchRecipe` | 按食材匹配菜谱 |

步骤：

1. 在开发者工具资源管理器中，右键每个云函数目录（如 `cloudfunctions/userManage`）。
2. 选择 **「上传并部署：云端安装依赖」**（不要选"所有文件"，避免本地无依赖包）。
3. 依次完成 5 个函数的上传。

> 注意：`recipeCRUD` 使用了内容安全接口 `security.msgSecCheck`（目录内已含 `config.json` 声明权限）。若部署后调用报权限错误，请在云开发控制台 → 云函数 → 配置 → 「微信开放接口权限」中手动勾选 `security.msgSecCheck`。

## 四、初始化数据库

1. 开发者工具顶部 **「云开发」→「云函数」**，找到 `initDatabase`。
2. 点击 **「云端测试」**，直接运行（入参留空即可），返回：

```json
{ "code": 0, "data": { "created": [...], "existed": [...] }, "msg": "ok" }
```

3. 回到 **「数据库」** 面板，确认集合已创建：

`users`、`recipes`、`categories`、`carts`、`orders`、`dinner_parties`（另有后期预留的 `favorites`、`posts`、`comments`、`fridge_items`）。

## 五、建议索引（数据库面板 → 对应集合 → 索引管理）

| 集合 | 索引字段 |
| --- | --- |
| users | `_openid`（唯一） |
| recipes | `_openid` + `isPublic` + `createdAt` |
| categories | `_openid` + `sort` |
| carts | `_openid` + `partyId` |
| orders | `_openid` + `status`、`orderNo`（唯一）、`participants` |
| dinner_parties | `_openid` + `status`、`inviteCode`（唯一） |

> MVP 数据量小可不建索引；用户量上来后再建，避免全表扫描。

## 六、真机测试要点清单

1. **登录**：首次打开小程序 → 「我的」页应显示默认昵称"美食爱好者"与默认头像。
2. **分类**：新用户自动生成 7 个默认分类（荤菜/素菜/鱼虾海鲜/汤羹/凉菜/主食/甜品）；「分类管理」可增改删。
3. **菜谱**：新增菜谱（传封面、食材、步骤、标签、公开开关）→ 厨房首页可见 → 编辑/删除正常 → 菜谱计数正确。
4. **购物车**：菜谱详情「加入购物车」→ 购物车改数量/备注/移除 → 提交订单 → 订单页出现"待确认"订单。
5. **饭局点菜（核心）**：
   - 用户 A 发起饭局 → 复制邀请码 / 转发分享卡片给用户 B；
   - 用户 B 通过邀请码加入 → B 添加菜品 → A 的房间 5 秒内轮询刷新可见；
   - A 提交订单 → 订单生成（参与人含 A、B），饭局状态变"已下单"，双方订单页均可见该订单；
   - A（发起人）可结束饭局；结束后不可再加菜、不可再入局。
6. **配菜**：「我的 → 按食材配菜」添加食材（含快捷点选）→ 匹配结果按匹配度排序，缺少食材红字提示 → 点击进入菜谱详情。
7. **资料**：改昵称 / 微信头像快速填写（或相册选图）→ 保存后全局同步（分享、饭局参与者、加菜人昵称随之更新）。
8. **订单流转**：发起人"开始制作 → 完成订单"；pending 状态可取消；非法状态操作应被拒绝。
9. **异常场景**：断网调用应有 toast 提示、不白屏；加入过期邀请码应提示"邀请码无效或饭局已结束"。

## 七、常见问题

| 现象 | 原因 / 处理 |
| --- | --- |
| 调用云函数报 `-404011` 或 `FunctionName parameter could not be found` | 云函数未部署，按第三节重新上传 |
| 云函数报 `Cannot find module 'wx-server-sdk'` | 部署时未选"云端安装依赖"，重新上传 |
| 新用户登录失败 | 未执行第四节初始化，或数据库权限被改为"仅创建者可读写"以外选项（保持默认即可，业务全部走云函数） |
| msgSecCheck 报权限错误 | 见第三节注意事项，需在云开发控制台开通接口权限 |
| 图片上传失败 | 云开发控制台 **「存储」** 权限保持默认（所有用户可读，仅创建者可读写） |

- [x] 分类管理：增删改，带菜谱计数
- [x] 购物车：加入 / 数量步进 / 备注 / 移除 / 合计
- [x] 下单与订单：个人下单、订单列表（状态筛选 + 分页）、订单详情、状态流转（待确认 → 制作中 → 已完成 / 已取消）
- [x] 邀请下单（饭局点菜）：发起饭局、分享链接邀请好友进入、共享发起人菜单池、多人各自加菜、实时轮询同步、按人分组展示、每人只提交自己的订单、只能删除自己点的菜、发起人可结束饭局

- [x] 基础设施：云函数统一返回结构与错误 toast、登录态封装、图片上传、空状态组件
