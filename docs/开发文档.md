### 1.2 技术选型确认

| 层级 | 技术 | 版本/说明 |
|------|------|----------|
| 小程序框架 | 微信原生 | 基础库 2.20.0+ |
| 开发语言 | TypeScript | 严格模式 |
| 组件框架 | glass-easel | 微信原生组件 |
| 后端 | 微信云开发 | 云函数 + 云数据库 + 云存储 |
| UI 组件库 | TDesign Miniprogram | 待用户确认 |
| AI 服务 | 豆包 / 通义千问 | 待用户确认 |
| 内容审核 | 微信 security.msgSecCheck | 云函数调用 |
| 状态管理 | 小程序原生 globalData + 本地缓存 | 无需额外引入 |

### 1.3 渲染与性能策略

- **Skyline 渲染**：已启用 `skylineRenderEnable: true`，使用 Worklet 动画
- **按需加载**：`lazyCodeLoading: requiredComponents`
- **分包加载**：主包放核心页面（厨房/订单/我的），厨神圈、AI配菜放分包
- **图片优化**：云存储 CDN + `lazy-load` + 压缩上传
- **列表优化**：`wx:key` 用稳定 ID，避免 `*this`

## 四、云函数接口设计

> 统一约定：所有云函数通过 `wx.cloud.callFunction({ name, data })` 调用  
> 统一返回格式：`{ code: 0, data: {}, msg: 'ok' }`，code 非0为异常

### 4.1 recipeCRUD（菜谱管理）

#### createRecipe — 创建菜谱
```
入参:
{
  title, coverImage, description, categoryId,
  difficulty, cookTime, servings,
  ingredients: [{name, amount, unit}],
  steps: [{order, text, image}],
  tips, tags, isPublic
}
返回: { _id }
逻辑: 内容审核 → 写入recipes → 更新categories.recipeCount
```

#### updateRecipe — 更新菜谱
```
入参: { _id, ...更新字段 }
返回: { updated: true }
逻辑: 校验创建者权限 → 内容审核 → 更新
```

#### deleteRecipe — 删除菜谱
```
入参: { _id }
返回: { deleted: true }
逻辑: 校验权限 → 软删除/物理删除 → 更新分类计数
```

#### getRecipeList — 菜谱列表
```
入参: { categoryId?, keyword?, tags?, filter: 'all'|'mine'|'favorite', page, pageSize }
返回: { list: [...], total, page, pageSize }
逻辑: 按条件查询，分页，关联用户信息
```

#### getRecipeDetail — 菜谱详情
```
入参: { _id }
返回: { recipe, author, isFavorite, isLiked }
逻辑: 查询详情 + 浏览数+1 + 查作者信息 + 查当前用户收藏/点赞状态
```

#### getCategories — 分类列表
```
入参: 无
返回: { list: [...] }
```

#### saveCategory — 保存分类（新增/更新）
```
入参: { _id?, name, icon, sort }
返回: { _id }
```

#### deleteCategory — 删除分类
```
入参: { _id }
返回: { deleted: true }
逻辑: 分类下菜谱移至"未分类"
```

#### addToCart — 加入购物车

#### getCartList — 购物车列表

#### createOrder — 创建订单
```
入参: { partyId?, remark }
返回: { orderId, orderNo }
逻辑: 读取购物车 → 生成订单号 → 写入orders → 清空购物车 → 若有关联饭局则更新状态
```

#### getOrderList — 订单列表

### 5.5 服务层设计

`utils/request.ts` 统一封装云函数调用：
```typescript
export const callFunction = async (name: string, data: any = {}) => {
  const res = await wx.cloud.callFunction({ name, data })
  const result = res.result
  if (result.code !== 0) {
    wx.showToast({ title: result.msg || '请求失败', icon: 'none' })
    throw new Error(result.msg)
  }
  return result.data
}
```

各业务服务继承此封装，例如 `services/recipe.ts`：
```typescript
import { callFunction } from '../utils/request'

export const recipeService = {
  getList: (params) => callFunction('recipeCRUD', { action: 'getRecipeList', ...params }),
  getDetail: (id) => callFunction('recipeCRUD', { action: 'getRecipeDetail', _id: id }),
  create: (data) => callFunction('recipeCRUD', { action: 'createRecipe', ...data }),
  // ...
}
```

### 6.2 AI 生成菜谱流程

```
用户输入食材/口味
       │
       ▼
  aiGenerateRecipe云函数
       │
       ├─ 拼装 Prompt
       │   "你是一个专业厨师，请根据以下食材生成菜谱：
       │    食材：番茄、鸡蛋
       │    口味：清淡
       │    人数：2人
       │    请返回JSON格式：{title, ingredients:[{name,amount,unit}], steps:[{text}], tips}"
       │
       ▼
  调用大模型 API（密钥在环境变量）
       │
       ▼
  解析返回 JSON
       │
       ▼
  返回前端展示
       │
       ├─ 用户可「保存为菜谱」→ createRecipe
       └─ 用户可「重新生成」
```

### 6.3 食材匹配菜谱流程

```
用户选择食材 ['番茄','鸡蛋','葱']
       │
       ▼
  matchRecipe.matchByIngredients
       │
       ├─ 查询所有 isPublic=true 的菜谱
       ├─ 对每个菜谱计算匹配度：
       │   matchScore = 交集食材数 / 菜谱食材数
       ├─ 标记缺失食材
       └─ 按 matchScore 降序排序
       │
       ▼
  返回 [{recipe, matchScore, missingIngredients}]
```

## 七、开发规范

### 7.1 命名规范

| 类型 | 规范 | 示例 |
|------|------|------|
| 页面/组件目录 | 小写+连字符 | recipe-detail |
| TS 文件 | 小驼峰 | recipeService |
| 组件名 | 大驼峰 | RecipeCard |
| 云函数 | 小驼峰 | recipeCRUD |
| 数据库集合 | 小写下划线 | recipe_versions |
| CSS 类名 | BEM | recipe-card__title |

### 7.2 TypeScript 规范

- 严格模式已开启（`strict: true`）
- 所有接口必须定义类型，禁止 `any`（`e: any` 事件除外，尽量用具体类型）
- 云函数返回值在 `types/` 中定义对应 interface

### 7.3 云函数开发规范

- 每个云函数 `index.js` 统一入口：
```javascript
exports.main = async (event, context) => {
  const { action, ...params } = event
  const { OPENID } = cloud.getWXContext()
  // 根据 action 分发
}
```
- 统一返回：`{ code: 0, data, msg }`
- 错误处理：try-catch 包裹，code 非0返回错误信息
- 日志：关键步骤 `console.log` 记录

### 7.4 Git 提交规范

```
feat: 新增菜谱创建功能
fix: 修复购物车数量计算错误
docs: 更新开发文档

```

## 十、风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| AI 生成内容不稳定 | 菜谱质量参差 | Prompt 约束 JSON 格式 + 前端二次校验 |
| 云函数冷启动延迟 | 首次调用慢 | 定时触发预热 + 核心函数保活 |
| 图片存储成本 | 云存储费用 | 上传前压缩 + 定期清理无用图片 |
| 内容违规 | 审核风险 | 接入 msgSecCheck + 举报机制 |
| 数据库查询性能 | 列表加载慢 | 合理建索引 + 分页 + 热门数据缓存 |
